PART 2 — THE UPGRADE PLAN (Prioritized)
================================================================================

TIER 1: MUST-HAVE (Biggest impact, least effort)

1. LENIS SMOOTH SCROLL
   Install: npm install lenis
   Wrap the entire app. This alone makes the site feel 10x more premium.

2. GSAP SCROLLTRIGGER SECTION REVEALS
   Install: npm install gsap @gsap/react
   Every section on every page fades/slides up as it enters viewport.
   Easing: power3.out (maps to your cubic-bezier(0.16, 1, 0.3, 1))
   Duration: 0.8s
   Stagger: 0.1s between children

3. PAGE TRANSITIONS
   Between route changes, fade out current page, fade in new page.
   Duration: 0.4s
   Use React Router's useLocation + AnimatePresence (framer-motion) OR
   GSAP timeline for exit/enter.

4. HERO TEXT STAGGER REVEAL
   On home page load:
   - "CREATIVE DEVELOPER" fades in first
   - "Python Backend Engineer" slides up with 0.15s delay
   - "Building Async Data Pipelines" slides up with 0.3s delay
   - Bio text fades in with 0.45s delay
   - Buttons fade in with 0.6s delay

5. PROJECT CARD HOVER EFFECTS
   On hover:
   - Card lifts (translateY: -8px)
   - Subtle teal glow shadow appears
   - Image inside scales slightly (1.05)
   - "View Project" text shifts right with arrow
   Duration: 0.3s, ease: power2.out

TIER 2: HIGH IMPACT (Medium effort)

6. CUSTOM CURSOR
   Small teal dot (8px) replacing default cursor.
   On hover over links/buttons: scales to 32px, inverts color.
   On hover over project cards: scales to 48px with "View" text inside.

7. MOUSE-REACTIVE PARTICLE BACKGROUND
   Your existing particle network should subtly react to mouse position.
   Particles near cursor get brighter / larger.

PART 8 — BIDIRECTIONAL SCROLL ANIMATIONS (CRITICAL)
================================================================================

REQUIREMENT: Every scroll animation must reverse when scrolling up.
If text slides up on scroll-down, it must slide back down on scroll-up.
If a card fades in on scroll-down, it must fade out on scroll-up.
This is non-negotiable. It makes the site feel like a physical surface.

---

GSAP SCROLLTRIGGER — BIDIRECTIONAL PATTERNS

PATTERN A: Scrub (Smooth bidirectional, recommended for most reveals)

useGSAP(() => {
  gsap.fromTo('.reveal-item', 
    { y: 60, opacity: 0 },
    {
      y: 0,
      opacity: 1,
      duration: 1,
      ease: 'power3.out',
      stagger: 0.1,
      scrollTrigger: {
        trigger: '.section-container',
        start: 'top 80%',
        end: 'top 30%',
        scrub: 1,        // <-- KEY: Smooth bidirectional
      }
    }
  )
}, { scope: sectionRef })

Behavior:
- Scroll down: items animate from → to
- Scroll up: items animate to → from (reverse)
- Smooth, tied directly to scroll position

---

PATTERN B: Toggle Actions (Snap bidirectional, for dramatic entrances)

useGSAP(() => {
  gsap.from('.reveal-item', {
    y: 80,
    opacity: 0,
    duration: 0.8,
    ease: 'power3.out',
    stagger: 0.1,
    scrollTrigger: {
      trigger: '.section-container',
      start: 'top 75%',
      toggleActions: 'play reverse play reverse',  // <-- KEY
    }
  })
}, { scope: sectionRef })

Behavior:
- Scroll down into view: plays forward
- Scroll up out of view: plays reverse
- Scroll down out of view: plays forward again
- Scroll up into view: plays reverse again

The four values are: onEnter, onLeave, onEnterBack, onLeaveBack
"play reverse play reverse" = play on enter, reverse on leave, play on enterBack, reverse on leaveBack

---

PATTERN C: Scrub + Pin (For pinned sections like the Hero sequence)

useGSAP(() => {
  const tl = gsap.timeline({
    scrollTrigger: {
      trigger: '.pinned-section',
      start: 'top top',
      end: '+=200%',      // Pin for 2 viewports of scroll
      pin: true,
      scrub: 1,           // Bidirectional
    }
  })

  tl.fromTo('.command-1', { opacity: 0, y: 30 }, { opacity: 1, y: 0 })
    .fromTo('.command-2', { opacity: 0, y: 30 }, { opacity: 1, y: 0 })
    .fromTo('.command-3', { opacity: 0, y: 30 }, { opacity: 1, y: 0 })

}, { scope: sectionRef })

Behavior:
- Scroll down: timeline progresses forward (command 1 → 2 → 3)
- Scroll up: timeline scrubs backward (command 3 → 2 → 1)
- The section stays pinned until fully scrubbed

---

PATTERN D: Count-Up Stats (Bidirectional with custom logic)

For stats that count up on scroll down, they should count down on scroll up.

useGSAP(() => {
  const stat = { value: 0 }

  gsap.to(stat, {
    value: 2027,
    duration: 1,
    ease: 'power2.out',
    scrollTrigger: {
      trigger: '.stats-section',
      start: 'top 80%',
      end: 'top 40%',
      scrub: 1,
      onUpdate: (self) => {
        // Update DOM with current value
        document.querySelector('.stat-year').textContent = Math.round(stat.value)
      }
    }
  })
}, { scope: sectionRef })

CRITICAL CONFIGURATION

Always set these defaults at app initialization:

gsap.defaults({ ease: 'power3.out', duration: 0.8 })

ScrollTrigger.defaults({
  toggleActions: 'play reverse play reverse',  // Default bidirectional
})

// For scrubbed animations, always use:
// scrub: 1 (or true) — NOT scrub: false

---

PERFORMANCE NOTE

Bidirectional animations with scrub can be heavy if not optimized:
- Use transform and opacity only (GPU-accelerated)
- Avoid animating layout properties (width, height, margin)
- Use will-change sparingly: will-change: transform, opacity
- Kill ScrollTriggers on component unmount:

useEffect(() => {
  return () => {
    ScrollTrigger.getAll().forEach(t => t.kill())
  }
}, [])
